# 反爬、质量与生产化要点

## 反爬升级顺序

遇到阻断时，按下面顺序逐级升级，不要一步到位上最重方案：

1. 降速：降低并发、增加间隔。
2. 补头：使用合理的 `User-Agent`、语言、引用来源。
3. 会话：保留 Cookie、登录态、会话池。
4. 指纹：浏览器指纹一致化。
5. 代理：机房代理到住宅代理逐步升级。
6. 浏览器：只在页面交互必须时使用完整浏览器。

## 质量控制

### 选择器稳定性优先级

1. `role`
2. `data-testid`
3. `label`
4. 可见文本
5. CSS / XPath

### 避免的反模式

- 有 API 还去解析 HTML。
- 有 sitemap 还去逐页点列表。
- 用固定 `sleep` 代替等待条件。
- 没有样本验证就直接全量跑。
- 没有唯一键就直接写入结果，导致重复。

## 生产化最小清单

当抓取要进入持续运行阶段，至少补齐：

- 输入参数定义
- 去重键
- 重试与超时
- 失败日志
- 小批量 smoke test
- 断点续跑或增量策略
- 输出目录和命名约定

## Apify / Crawlee 场景

当用户要求部署或 Actor 化时：

- 优先 TypeScript。
- 用 `apify create` 初始化，不要手搓项目骨架。
- 先保留当前最小可行逻辑，再逐步补监控、代理和输入 schema。
